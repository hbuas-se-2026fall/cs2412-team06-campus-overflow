# 团队代码评审清单 v1.0（QA · 王）

> 适用：CampusOverflow 后端（Java 21 / Spring Boot 3 / Maven 多模块 DDD）与前端（React 18 / TypeScript 5 / Vite）所有 PR。
> 依据：团队章程 v1.0 第 3（评审不形式化）、第 5（DoD）、第 6/7/8 节。
> 使用方式：评审人从本清单逐项核对；每个 PR 至少留下 1 条实质性意见（章程要求），Lab7 深度评审每 PR 至少 5 条；意见区分「阻塞 / 建议 / 疑问」。

## 一、评审动作规范

1. **先读 PR 描述**：确认任务目标、关联故事/Task、是否对应 DoD。
2. **按维度过清单**：正确性优先，再看架构边界、安全、测试、风格。
3. **意见可操作**：指出位置 + 问题 + 建议改法，不写「这里不太好」这类空话。
4. **结论分级**：
   - 阻塞（必须改）：正确性错误、越权、不变式被破坏、编译/测试失败。
   - 建议（可后续）：可读性、重复、命名、性能小优化。
   - 疑问：设计取舍不清，请求作者说明。
5. **不形式化**：禁止只回 LGTM / 👍；至少 1 条带具体位置的意见。
6. **自评在先**：作者提 PR 前先跑通 typecheck / lint / 相关测试并在描述里写明结果。

## 二、正确性与业务逻辑

| # | 检查问题 | 通过标准 |
| --- | --- | --- |
| C-01 | 业务规则与验收标准一致吗？ | 实现与 Gherkin 场景/Backlog 验收标准逐条对应，快乐路径正确 |
| C-02 | 聚合不变式被保护了吗？ | 标题/正文/标签/票数等约束在领域层校验；Setter 私有化，经聚合方法修改 |
| C-03 | 边界条件处理了吗？ | 空值、分页越界、0 票、撤票、重复提交、目标不存在 |
| C-04 | 异常路径有对应处理吗？ | 未登录 401、无权 403、参数非法 400、不存在 404、状态冲突 409 |
| C-05 | 金额/分值/计数计算正确吗？ | 投票增量、采纳/撤销计数、标签计数增减与回滚一致 |
| C-06 | 有没有副作用遗漏？ | 领域事件发布、标签使用计数、回答数/票数统计同步更新 |

## 三、DDD 架构边界（后端）

| # | 检查问题 | 通过标准 |
| --- | --- | --- |
| A-01 | 依赖方向正确吗？ | interfaces → application → domain；infrastructure 实现 application 端口，无反向依赖 |
| A-02 | 跨上下文只走对方 api 模块吗？ | 不直接依赖其他上下文 application/infrastructure；跨上下文经契约事件或 *-api 接口 |
| A-03 | 领域层零框架依赖吗？ | domain 不出现 Spring/JPA/Redis 注解与类型，可脱离容器跑单测 |
| A-04 | 领域对象与持久化实体分离了吗？ | 遵循 ADR-008，JPA Entity 与领域实体有映射，不把实体当聚合根暴露 |
| A-05 | 包结构符合限界上下文划分吗？ | 对照 ADR-009，改动收敛在所属模块内，无跨层混杂 |

## 四、安全与权限

| # | 检查问题 | 通过标准 |
| --- | --- | --- |
| S-01 | 认证与会话校验了吗？ | 需要登录的接口有会话/Token 校验；未访问返回 401 |
| S-02 | 授权（越权）检查了吗？ | 编辑/删除/采纳/管理操作校验作者本人或课程教师/管理员角色，越权 403 |
| S-03 | 输入做了校验与清洗吗？ | 长度/格式/枚举值校验；Markdown 渲染走安全转义，防 XSS；标签名非法字符拦截 |
| S-04 | 敏感信息处理得当吗？ | 密码加密存储，不明文返回/打日志；日志不记录口令、Token |
| S-05 | 查询参数可注入吗？ | 使用参数化查询/ORM，不拼接 SQL；排序、分页字段白名单 |

## 五、可测性与测试

| # | 检查问题 | 通过标准 |
| --- | --- | --- |
| T-01 | 新增/修改逻辑有测试吗？ | 核心聚合行为、命令服务有单测；新功能不允许无测试进 main（DoD） |
| T-02 | 断言有效吗？ | 验证状态与副作用调用；不存在「调用了就算过」的空断言 |
| T-03 | 测试独立、可重复吗？ | 不依赖外部服务/顺序；领域单测不起 Spring 容器 |
| T-04 | 异常路径有测试吗？ | 至少覆盖无权、非法参数、不存在、冲突等分支 |
| T-05 | 测试命名表达意图吗？ | 方法名说明场景与预期（如 `rejectsTagsExceedingFive`） |

## 六、可读性与可维护性

| # | 检查问题 | 通过标准 |
| --- | --- | --- |
