# 高优先级用户故事验收用例（Gherkin）

> 格式：Given-When-Then
> 用途：把模糊的需求变成可测试的具体场景

---

## US-002 发布问题

### 场景1：正常发布问题（快乐路径）
```gherkin
Scenario: 学生成功发布一个问题
  Given 我是已登录的学生用户
  And 我在发布问题页面
  When 我填写标题："Java的多态是什么意思？"
  And 我填写内容："上课没听懂，求大佬解释一下"
  And 我选择标签：Java
  And 点击发布按钮
  Then 系统应该提示"发布成功"
  And 跳转到这个问题的详情页
  And 问题列表里能看到这条新问题
```

### 场景2：标题为空（异常路径）
```gherkin
Scenario: 标题为空时不能发布
  Given 我是已登录的学生用户
  And 我在发布问题页面
  When 我把标题留空
  And 填写了问题内容
  And 点击发布按钮
  Then 系统应该提示"标题不能为空"
  And 不会创建新问题
```

### 场景3：未登录用户不能发布
```gherkin
Scenario: 未登录用户尝试发布问题
  Given 我没有登录
  When 我直接访问发布问题页面
  Then 系统应该跳转到登录页面
  And 提示"请先登录后再提问"
```

## US-003 浏览问题列表

### 场景1：游客浏览问题列表
```gherkin
Scenario: 游客看到所有已发布的问题
  Given 系统里已经有5个已发布的问题
  When 我打开问题列表首页
  Then 我应该看到最新发布的问题排在最上面
  And 每个问题显示：标题、作者、发布时间、回答数
```

## US-005 回答问题

### 场景1：学生成功回答问题
```gherkin
Scenario: 学生对问题发表回答
  Given 我是已登录的学生用户
  And 我正在查看一个问题的详情页
  When 我在回答框输入："多态就是同一个接口不同实现……"
  And 点击提交回答
  Then 系统应该提示"回答成功"
  And 这条回答显示在回答列表最上面
```

### 场景2：不能回答自己的问题
```gherkin
Scenario: 提问者不能回答自己的问题
  Given 我是这个问题的提问者本人
  When 我查看自己提的问题的详情页
  Then 页面上不应该显示回答输入框
  And 提示"不能回答自己的问题"
```

## US-006 投票功能

### 场景1：给回答点赞
```gherkin
Scenario: 学生给好回答点赞
  Given 我是已登录的学生用户
  And 我正在查看问题详情页
  When 我给某条回答点了赞
  Then 这条回答的票数应该+1
  And 按钮变成已点赞状态
```

### 场景2：重复投票无效
```gherkin
Scenario: 同一个用户不能重复投同一条回答
  Given 我已经给这条回答点过赞了
  When 我再次点击点赞按钮
  Then 票数不应该变化
  And 系统提示"你已经投过票了"
```
