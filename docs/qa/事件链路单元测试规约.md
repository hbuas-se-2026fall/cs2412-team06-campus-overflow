## 二、事件契约（跨上下文只走 `*-api` 模块记录的集成事件）

| 事件（record） | 字段 | 声誉侧用途 |
| --- | --- | --- |
| `UserRegisteredEvent` | `eventId, occurredAt, userId, displayName, role` | 开户：按角色发初始悬赏积分 |
| `VoteCastEvent` | `eventId, occurredAt, targetType, targetId, targetAuthorId, voterId, questionId, oldValue, newValue` | 投票变更：按 `new − old` 计算声誉增量；`old/new ∈ {-1,0,1}`；`targetType ∈ QUESTION/ANSWER` |
| `AnswerAcceptedEvent` | `eventId, occurredAt, answerId, questionId, answerAuthorId, questionAuthorId, acceptedById, questionTitle` | 采纳结算：回答者 +15（自问自答不加分） |
| `AnswerSubmittedEvent` | `eventId, occurredAt, answerId, questionId, answerAuthorId, questionAuthorId, questionTitle` | 预留（声誉侧规则待后端确认是否加分） |
| `AnswerEndorsedEvent` | `eventId, occurredAt, answerId, questionId, answerAuthorId, endorserId, questionTitle` | 教师认证标记，声誉规则待后端确认 |

**幂等键**：`(sourceEventId, userId, reason)`，对应 `LedgerRepository.exists(eventId, userId, reason)`；`reason ∈ ReputationReason`：`ANSWER_ACCEPTED / QUESTION_VOTE / ANSWER_VOTE / BOUNTY_AWARDED`。

## 三、链路测试设计

### 链路 1：注册 → 声誉账户初始化

- **触发**：`UserRegisteredEvent(userId, role)`。
- **处理器**：`ReputationEventHandlers.on(UserRegisteredEvent)`。
- **规则**：`initialPoints(role)` —— `TEACHER = 1000`，`STUDENT = 0`（待后端实现后以 Rulebook 为准复核）；开户后 `availablePoints = initialPoints`，`frozenPoints = 0`，`reputation = 0`。
- **断言清单**：
  1. 学生注册 → 开户成功，悬赏积分 0，声誉 0。
  2. 教师注册 → 开户成功，悬赏积分 1000，声誉 0。
  3. 同一 `eventId` 重复投递 → 不重复开户、不二次发放积分（幂等）。
- **被测类/方法**：`ReputationAccount.open`、`ReputationRulebook.initialPoints`、`ReputationEventHandlers.on(UserRegisteredEvent)`。
- **现状**：全部 TODO，用例待后端实现后落地。

### 链路 2：投票 → 声誉变更

- **触发**：`VoteCastEvent(targetType, targetAuthorId, oldValue, newValue)`。
- **处理器**：`ReputationEventHandlers.on(VoteCastEvent)`；记账走 `ReputationLedgerService.record`。
- **规则（Rulebook）**：
  - 效果映射 `voteEffect`：`+1 → UPVOTE(+10)`，`−1 → DOWNVOTE(−2)`，`0 → 0`。
  - 增量 `voteDelta(old, new) = voteEffect(new) − voteEffect(old)`。
  - 每日正向投票上限 `DAILY_VOTE_CAP = 200`：正向增量受上限约束，负向增量不受限（`applyDailyCap`）。
  - `reason`：`targetType=QUESTION → QUESTION_VOTE`，`ANSWER → ANSWER_VOTE`；不计被投票者给自己投票（投自己拦截在 qa 侧，声誉侧只收合法事件）。
- **断言清单（沿用现有参数化用例口径）**：

  | oldValue | newValue | 预期 delta |
  | --- | --- | --- |
  | 0 | 1 | +10 |
  | 0 | −1 | −2 |
  | 1 | 0 | −10（撤销赞） |
  | −1 | 0 | +2（撤销踩） |
  | 1 | −1 | −12（赞改踩） |
  | −1 | 1 | +12（踩改赞） |

  - 日上限：当日已累计正向 195，本次 +10 → 记 +5；已累计 200，本次 +10 → 记 0；负向 −2 不受上限影响。
  - 重复事件（同 `eventId + targetAuthorId + reason`）→ 忽略，不二次记账。
- **被测类/方法**：`Rulebook.voteEffect / voteDelta / applyDailyCap`、`ReputationEventHandlers.on(VoteCastEvent)`、`LedgerService.record`。
- **现状**：规则方法与处理器 TODO；`record` 查重骨架在。

### 链路 3：采纳 → +15

- **触发**：`AnswerAcceptedEvent(answerAuthorId, questionAuthorId)`。
- **处理器**：`ReputationEventHandlers.on(AnswerAcceptedEvent)`。
- **规则**：`acceptedDelta(answerAuthorId, questionAuthorId)` —— 相等（自问自答）→ 0；否则回答者 `+15`，`reason = ANSWER_ACCEPTED`。
- **断言清单**：
  1. 回答者 ≠ 提问者 → 回答者声誉 +15，落一条 `ANSWER_ACCEPTED` 流水。
  2. 回答者 = 提问者（自答被采纳）→ 增量 0，不落加分流水。
  3. 重复投递同一采纳事件 → 幂等忽略。
- **被测类/方法**：`Rulebook.acceptedDelta`（已实现，现有 `selfAcceptedAnswerEarnsNothing` 绿测已覆盖）、`on(AnswerAcceptedEvent)`、`Account.applyReputation`、`LedgerService.record`。
- **现状**：仅 `acceptedDelta` 已实现；处理器/账户记账 TODO。

### 链路 4：重复事件幂等（记账核心）

- **被测**：`ReputationLedgerService.record(userId, sourceEventId, reason, delta, refType, refId)`。
- **规则**：
  1. `delta == 0` → 返回 `false`，不写流水、不发事件。
  2. `ledger.exists(sourceEventId, userId, reason) == true`（重复事件）→ 返回 `false`，不写流水、不发事件。
  3. 首次且 `delta ≠ 0` → 查/开户 → `applyReputation(delta)` → 追加 `LedgerEntry` → 发布 `ReputationChangedEvent` → 按新声誉授予徽章；返回 `true`。
- **幂等键**：`(sourceEventId, userId, reason)`；流水 `LedgerEntry.of(...)` 只追加。
- **现状**：第 1、2 条早返回路径可在不触发 TODO 方法的前提下写绿测（见第五节）；第 3 条真实记账路径依赖 `Account.open/applyReputation` TODO，暂不可测。
